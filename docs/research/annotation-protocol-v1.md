# RCNC 标注与冻结规范 v1

本规范区分源材料证据、作者世界设定与独立语义复核。当前版本是实验协议，不代表标注已完成。

## 标注单位与状态

- 普通动作参数：SOURCE:action + parameter，记录类型、所需能力及证据。
- 谓词接口：双方声明、参数方向/顺序、类型、等价或其他关系。当前执行仅接受显式同签名映射。
- 源常量角色：允许身份替换范围、类型、能力与互异关系。
- 对象能力：明确是源材料事实还是本任务作者设定；缺失标注不等于现实中无该能力。

状态使用 `unreviewed`、`author_hypothesis`、`independently_supported`、`rejected`、`uncertain`。不能因 PDDL 可解析、计划可执行或动作名称看起来合理，就升级为 independently_supported。

当前所有三项参数约束仍为 author_hypothesis，独立复核数为零。

## 每条记录必须包含

1. 唯一单位标识及源文件/材料版本。
2. 原声明与动作中实际使用位置。
3. 提议约束；区分必要前提与仅为典型用途的偏好。
4. 可定位证据及证据类别：原故事语句、领域说明、作者新增世界设定或尚无证据。
5. 标注者标识、判断、理由与日期。
6. 若存在分歧，保留双方原判断和最终处理依据，不覆盖原记录。

仅凭 `boots`、`key` 等词名提出的约束，仍须标记为假设。对魔法/多功能物品，应明确世界设定，不能为了让任务可解临时增加能力。

## 独立复核流程

建议由两名未查看当前任务求解结果的标注者分别判断。结果输出应保存在新文件，不修改冻结队列。先报告两人的原始一致性，再讨论分歧。模糊或缺少材料时保留 uncertain，不强行补齐。

当前已提供待审队列 `data/rcnc/frozen_protocol_v1/annotation_queue.json`，覆盖 571 个普通参数槽位。它是任务清单，不是已完成的 571 条语义标注。接口和角色的完整覆盖统计尚需另建清单。

## 冻结与版本管理

- 在求解前生成 registry、所有任务、固定选择规则和 split，再生成 freeze.json。
- freeze.json 固定任务、登记、待审队列、源 PDDL、RCNC 模块及生成/运行脚本 SHA256。
- 执行前后验证内容一致；运行中保留逐任务 progress 和全部最终结果。
- 发现标注问题可创建 v2，但不得覆盖 v1 或抹去失败任务。若依据测试结果修改规则，受影响任务随后属于开发数据。
- 哈希用于检测版本漂移，不是第三方签名或不可篡改存证。依赖环境另行记录。

## 数据划分的准确名称

- development：已有讨论和观察影响过的参照任务。
- prospective_variant：规则冻结后首次执行的、由已知模型生成的变体。
- independent_test：来自独立来源或按预先规定留出的数据，规则未针对其结果调整。

当前 v1 只有前两类。prospective_variant 不能宣传为新领域泛化或独立测试集。物品能力的不同设定属于不同输入模型，也不能合并为同一语义条件的算法胜率。

## 报告要求

分别报告各 split 的任务数、赋值数、独立验证状态、不可解及预算截断、来源必要性和标注覆盖。单来源可解与人为不可解控制均保留。未经独立复核的约束不得当作 gold annotation。
